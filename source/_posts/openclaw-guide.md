## 🏗️ 第一篇：基础概念篇
我们把 OpenClaw 比作你开了一家 **AI 助理公司**，这样所有概念就都好懂了：
### 1.1 核心组件总览

| 技术名词 | 公司里的角色 | 生活化比喻 | 作用 |
|---------|-------------|-----------|------|
| **Gateway 网关** | 公司总部大楼 | 你家的总电闸 + 快递总站 | 所有功能的核心，管理所有消息、员工和设备 |
| **Session 会话** | 独立的办公室 | 微信的不同聊天窗口 | 每个窗口聊不同的话题，互相不打扰 |
| **Memory 记忆** | 公司档案库 | 你的笔记本 | 重要的事情写在本子上，永远不会忘 |
| **Channel 渠道** | 对外接待窗口 | 飞书、微信、电话等联系方式 | 用户可以通过不同方式找到你的助理 |

是不是一下子就懂了？接下来我们逐个细说：
### 1.2 Gateway 网关详解
Gateway 就是你这家 AI 公司的**总部大楼**，所有事情都在这里发生：
#### 1.2.1 核心功能
就像大楼管理员一样，Gateway 管这些事：
- 管大门：谁能进来（用户消息接入）
- 管分配：用户消息送到哪个办公室（会话路由）
- 管员工：安排智能体干活，调用各种工具
- 管后勤：记录所有聊天记录，备份重要数据
#### 1.2.2 大楼的"门"（端口）
Gateway 有几个固定的门，供不同功能使用：

| 门牌号（端口） | 用途 |
|--------------|------|
| 18789 | 正门，所有人都从这里进 |
| 18791 | 侧门，专门给浏览器工具用 |
| 18793 | 后门，给展示界面用 |

#### 1.2.3 怎么"开张营业"（启动 Gateway）
```bash
# 临时开张（关了终端就停止营业）
openclaw gateway

# 永久开张（安装成自动服务，开机就运行）
openclaw gateway install  # 先注册公司
openclaw gateway start    # 开始营业
openclaw gateway status   # 看看今天有没有开门
openclaw gateway restart  # 休息一下再营业
openclaw gateway stop     # 今天打烊啦

```

### 1.3 Session 会话详解
Session 就是公司里的**独立办公室**，每个办公室聊不同的项目：
#### 1.3.1 办公室类型
- **总裁办公室（主会话 main）**：你和助理的私人聊天，所有私人消息都在这里
- **项目会议室（群聊会话）**：每个群聊是一个独立会议室，大家在这里讨论项目
- **小会议室（话题会话）**：群里的某个话题单独开个小会，不打扰主会议室
- **自动办公室（定时任务）**：到点自动开门干活，比如每天早上发天气预报
#### 1.3.2 办公室在哪里（存储位置）
所有会议室的聊天记录都存在总部大楼里：
```plaintext
~/.openclaw/agents/你的助理ID/sessions/
├── 办公室列表.json           # 记录所有办公室的门牌号
├── 办公室1号.jsonl          # 1号办公室的所有聊天记录
└── 办公室1号-话题3号.jsonl  # 1号办公室里第3个话题的聊天记录

```

#### 1.3.3 办公室"重置"规则
就像会议室会定期打扫一样，会话也会自动重置：
- 总裁办公室每天凌晨4点打扫干净，开始新的一天
- 项目会议室没人用2小时后就打扫干净
- 小会议室每天凌晨4点统一打扫
手动打扫办公室（重置会话）：
```bash
# 在聊天里发这个命令就行
/new 或 /reset

```

> 🔍 常见疑问：用了 `/new` 之后之前的聊天记录去哪了？答：就像你打扫完会议室，之前的会议记录都存档了，并没有丢！回到之前的聊天窗口继续说话，就会重新打开那个会议室，之前的记录都还在。
### 1.4 Memory 记忆系统详解
记忆就是公司的**档案库**，重要的事情都会写在这里：
#### 1.4.1 档案分类

| 档案类型 | 存放位置 | 比喻 | 什么时候用 |
|---------|---------|------|-----------|
| 每日工作笔记 | `memory/2026-03-12.md` | 你的日常记事本 | 记录每天发生的事，最近两天的会自动放在助理桌上 |
| 重要档案 | `MEMORY.md` | 保险柜里的重要文件 | 记录长期不变的信息，只有在总裁办公室才能看 |

#### 1.4.2 你的"办公桌"上有什么（工作区文件）
你的助理的办公桌上永远放着这些文件：
```plaintext
你的工作区（默认 ~/.openclaw/workspace）/
├── 员工手册.md        # 告诉助理应该怎么工作
├── 人设要求.md        # 助理的性格、说话风格
├── 用户信息.md        # 你的名字、喜好、联系方式
├── 助理身份.md        # 助理的名字、头像、性格
├── 工具说明.md        # 各种工具怎么用
├── 待办清单.md        # 定期要检查的事情
├── 重要档案.md        # 长期记忆
└── 每日笔记/          # 每天的工作记录
    ├── 2026-03-10.md
    ├── 2026-03-11.md
    └── 2026-03-12.md

```

#### 1.4.3 智能"档案搜索"
就像你有一个超级能干的档案管理员：
- 你说"帮我找一下关于周三开会的记录"，即使你记不清具体日期，他也能找到相关内容
- 既会搜意思相近的内容，也会搜 exact 关键词
- 可以自己加其他档案柜，比如把公司的文档也加进来搜索
### 1.5 Channel 渠道详解
渠道就是你这家公司的**对外联系方式**：
#### 1.5.1 支持的联系方式

| 联系方式（渠道） | 特点 | 配置难度 |
|----------------|------|---------|
| 飞书 | 公司里最常用 | ⭐⭐ |
| Telegram | 注册最快，5分钟就能用好 | ⭐ |
| WhatsApp | 国外最常用，扫码就能用 | ⭐⭐ |
| Discord | 社区爱好者常用 | ⭐⭐ |
| 网页聊天 | 直接在浏览器里用 | ⭐ |
| iMessage | 苹果用户专属 | ⭐⭐⭐ |

#### 1.5.2 消息怎么流转
就像别人给你发消息：
1. 不管是飞书还是微信，消息先送到公司前台（Gateway）
1. 前台看是找谁的，送到对应的办公室（会话）
1. 助理处理完，写好回复，前台再通过原来的联系方式发回去

## 🛠️ 第二篇：操作实战篇
### 2.1 会议室（会话）管理实战
#### 2.1.1 看看现在有哪些会议室开着
```bash
# 列出所有会议室
openclaw sessions --json

# 看看最近半小时有人用的会议室
openclaw sessions --active 30

```

#### 2.1.2 怎么回到之前的会议室
> 🔍 很多人问：新建了会话之后怎么回去？
**方法一：最常用**
- 打开你之前聊天的那个窗口（飞书/微信/ Telegram 都一样）
- 直接发消息，自动就回到之前的会议室了
**方法二：手动指定**
```bash
# 给指定会议室发消息
openclaw message send --session 会议室门牌号 --message "你好"

```

#### 2.1.3 会议室常用"快捷键"

| 命令 | 作用 | 比喻 |
|-----|------|------|
| `/status` | 看看这个会议室现在的状态，用了多少"空间" | 看会议室里坐了多少人 |
| `/context list` | 看看现在会议室里有什么资料 | 看桌上放了什么文件 |
| `/compact` | 整理一下会议室的资料，腾出空间 | 把旧文件存档，桌面收拾干净 |
| `/stop` | 让助理停下现在干的活 | 打断正在汇报的员工 |
| `/new [模型名]` | 开个新的会议室，可选换个助理 | 换个新办公室，可选换个专家来 |

### 2.2 档案（记忆）管理实战
#### 2.2.1 让助理记住重要的事
```bash
# 直接说就行
"记住：我每周三下午2点都要开部门例会，别安排其他事"

# 找档案
"帮我找找关于周三例会的记录"

```

#### 2.2.2 备份你的档案
```bash
# 最简单的方法：把整个办公桌打包
tar -czf 我的助理备份.tar.gz ~/.openclaw/workspace

# 推荐方法：用 Git 备份，就像游戏存档一样
cd ~/.openclaw/workspace
git add .
git commit -m "2026-03-12 备份"
git push

```

#### 2.2.3 恢复档案
```bash
# 解压缩备份
tar -xzf 我的助理备份.tar.gz -C ~/.openclaw/workspace

# Git 恢复
cd ~/.openclaw/workspace
git pull

```

### 2.3 联系方式（渠道）配置实战
以飞书为例，就像给公司开通飞书账号：
1. 去飞书开放平台注册一个机器人"员工"
1. 拿到这个员工的工号（App ID）和密码（App Secret）
1. 告诉公司管理员（修改配置文件 `~/.openclaw/openclaw.json`）
```json
{
  "channels": {
    "feishu": {
      "enabled": true,
      "appId": "你的飞书机器人App ID",
      "appSecret": "你的飞书机器人App Secret"
    }
  }
}

```

1. 重启一下公司服务：`openclaw gateway restart`
### 2.4 总部（Gateway）管理实战
#### 2.4.1 看看公司运营状态
```bash
# 简单看一下有没有开门
openclaw gateway status

# 详细看一下运营健康状况
openclaw gateway health

# 看实时监控画面（日志）
openclaw logs --follow

```

#### 2.4.2 公司"规章制度"（配置文件）
位置：`~/.openclaw/openclaw.json`常用的规则：
```plaintext
{
  "session": {
    "reset": {
      "mode": "daily",      // 每天打扫一次会议室
      "atHour": 4,          // 凌晨4点打扫
      "idleMinutes": 120    // 没人用2小时就打扫
    }
  },
  "agents": {
    "defaults": {
      "workspace": "~/.openclaw/workspace",  // 办公桌位置
      "model": "anthropic/claude-3-opus"     // 用哪个级别的助理
    }
  }
}

```

## ❓ 第三篇：常见问题篇
### 3.1 会议室（会话）相关问题
**Q：我用了 /new 之后，之前的聊天记录找不到了怎么办？**A：就像你开了新的会议室，旧的会议室只是锁起来了，没有拆！回到之前的聊天窗口发个消息，旧会议室就开门了，所有记录都在。所有记录永久存在 `~/.openclaw/agents/你的助理ID/sessions/` 目录下。
**Q：会议室会自动拆掉吗？**A：不会。打扫只是把桌上的东西收走，房间和之前的记录都永久保留，除非你手动拆（删除文件）。
**Q：没用的会议室太多了怎么清理？**
```bash
# 拆掉指定的会议室
rm ~/.openclaw/agents/你的助理ID/sessions/会议室号.jsonl

# 拆掉所有30天没人用的会议室
find ~/.openclaw/agents/你的助理ID/sessions/ -name "*.jsonl" -mtime +30 -delete

```

### 3.2 档案（记忆）相关问题
**Q：为什么助理有时候会"忘了"之前说过的话？**A：两种可能：
1. 你换了新的会议室，桌上没有放之前的档案
1. 你没让他"记住"，他只是临时记在脑子里，打扫会议室就忘了
解决方法：重要的事说一句"帮我记住这件事"，他就会写进档案里，永远不会忘。
**Q：档案会不会占很多地方？**A：完全不会！都是纯文本，就像你写日记，写十年也只有几十MB，还不如一张照片大。
**Q：换电脑了怎么把记忆带过去？**A：把 `~/.openclaw/workspace` 目录复制过去就行，就像你把笔记本带到新公司一样。
### 3.3 总部（Gateway）相关问题
**Q：公司打不开门了（Gateway 启动失败）怎么办？**
```bash
# 先看看出什么事了
openclaw logs --tail 100

# 最常见原因：被别的公司占了地方（端口被占用）
lsof -i :18789  # 看看谁占了你的地址
kill -9 <进程ID>   # 把他赶走
openclaw gateway start  # 重新开门

```

**Q：我在外地怎么访问公司？**A：推荐用 Tailscale 虚拟专用网络，或者用 SSH 隧道：
```bash
ssh -N -L 18789:127.0.0.1:18789 你的用户名@公司服务器地址

```

**Q：可以开几家分公司吗（多 Gateway 实例）？**A：可以，但没必要。通常一家公司就够了，能同时接所有渠道的消息。如果需要隔离业务，可以用 `--dev` 参数开个分公司。

## 💡 第四篇：最佳实践篇
### 4.1 会议室（会话）使用最佳实践
- 总裁办公室用来和助理聊私人问题，保持连续性
- 不同的项目建不同的群聊/话题，自动隔离
- 重要的决策说一句"记住这个"，写入档案
- 会议室满了（上下文太长）就用 `/compact` 整理一下，提高效率
### 4.2 档案（记忆）管理最佳实践
- 每天的聊天记录自动存在每日笔记里，不用你管
- 定期整理重要档案，把没用的内容删掉
- 用 Git 备份，不怕数据丢失
- 密码、密钥这些敏感东西不要写在档案里，用密码管理器存
### 4.3 公司（Gateway）运维最佳实践
- 把公司设成开机自动启动，不用每次手动开门
- 定期备份整个 `~/.openclaw` 目录，就像给公司买保险
- 偶尔看看监控日志，有没有异常情况
- 每个月更新一次系统：`openclaw update`，用上最新功能
